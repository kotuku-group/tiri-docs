[[ch-logging-and-diagnostics]]
== Logging & Diagnostics
indexterm:[logging] indexterm:[diagnostics] **Implementation-specific.** This chapter documents behaviour specific to the Kōtuku/LuaJIT implementation and is not part of the language specification.

Tiri provides `print()` and `msg()` for diagnostic output.  The `DebugLog` method on Script objects captures structured runtime state, and `try<trace>` enables stack trace capture during exception handling.

[[sec-print-and-msg]]
=== Print & Msg
[discrete]
==== print()

[.api]`print(pass:[...])`

indexterm:[print] indexterm:[msg] Writes each argument to stderr after converting it to a string via `tostring()`.  No word-breaks are inserted between parameters.  A newline is appended after the final argument.

[source,tiri]
----
print('count:', 42, true)   -- "count:42true"
----

Raises an error if `tostring()` does not return a string for any argument.

On Android, output is redirected to the platform logging system.

TIP: Use `io.write()` for program output on stdout.

[discrete]
==== msg()

[.api]`msg(pass:[...])`

Writes each argument to the Kōtuku logging system at Info level, under the `Tiri` header.  Each argument is converted to a string via `tostring()` and written as a separate log entry, so a call with multiple arguments produces multiple log lines.

[source,tiri]
----
msg('request received')
msg(f'status: {result}') -- Inline formatting with f-strings
msg('status: ', result)  -- Two arguments: two log entries
----

Use `msg()` for diagnostic output that requires Kōtuku log filtering.  It is visible with `--log-info` or a more verbose level and writes to stderr.  Use an f-string to emit a single formatted entry.

Raises an error if `tostring()` does not return a string for any argument.

[[sec-log-levels]]
=== Log Levels
indexterm:[log levels] Kōtuku's logging system organises output by severity.  Log messages are written to stderr.  The following log levels are defined, from most to least verbose:

[cols="2,8a,3a",options="header"]
|===
|Level |Description |Command-line flag

|Trace
|Extremely verbose debug output.  Trace messages are compiled into Debug builds only; Release builds omit them entirely.
|`--log-trace` +
`--log-all`

|Debug
|Debug messages only appear in Debug builds.
|`--log-debug`

|Detail
|Extended log level for API modules (C++) and Tiri libraries.  For in-depth module diagnostics.
|`--log-xapi`

|API
|The standard level for API modules (C++) and Tiri libraries.
|`--log-api`

|Info
|The standard level for log messages originating from the client program.  This is the level used by `msg()`.
|`--log-info`

|Warning
|Non-catastrophic errors are printed as warnings.  API errors are always printed at this level (elevation to the user is at the program's discretion).
|`--log-warning` +
`--log-warn`

|Error
|Error conditions intended for end-user visibility.
|`--log-error`
|===

Each command-line flag enables its level and all levels above it.  For example, `--log-warning` displays warnings and errors.

`--log-none` suppresses all non-critical log output (including errors).

[source,bash]
----
origo script.tiri --log-warning   # Warnings and errors
origo script.tiri --log-api       # API messages and above
----

[[sec-debug-logging]]
=== Debug Logging
Calling the `DebugLog()` method on Script objects provides structured inspection of the Tiri runtime state.

[discrete]
==== script.mtDebugLog()

[.api]`err, result = script.mtDebugLog([Options])`

Captures a snapshot of the script's runtime state and returns it as a formatted string.  `Options` is a comma-separated string specifying which categories of information to include.  If `Options` is omitted, only the call stack is returned.

[cols="1,3a",options="header"]
|===
|Option |Description

|`stack`
|Call stack trace with source locations and line numbers.

|`locals`
|Local variables in the current scope, with names, types and values.

|`upvalues`
|Upvalue variables captured by the current closure.

|`globals`
|Global variables, with names and values.

|`memory`
|Heap usage reported by the garbage collector.

|`state`
|VM state information: the stack top and the active debug hook mask.

|`funcinfo`
|Function metadata: parameter count, vararg flag, stack slots, bytecode count, constants and upvalue count.

|`disasm`
|Bytecode disassembly of the current function.  `bytecode` is accepted as an alias.

|`dump`
|Binary dump of the function's bytecode in hexadecimal format.

|`all`
|Every category above except `dump`.

|`compact`
|Compact output mode.  Combine with other options to reduce verbosity.
|===

The `stack`, `locals` and `upvalues` categories require an active Tiri call frame and are therefore available only when `DebugLog()` is called from inside the script.  An external caller receives an empty section for those categories, and a warning is written to the log.

[source,tiri]
----
self = obj.find('self')

-- Capture call stack and local variables
err, result = self.mtDebugLog('stack,locals')
print(result)

-- Capture everything in compact form
err, result = self.mtDebugLog('all,compact')
----

String values longer than 40 characters are truncated with an ellipsis in the output.

[[sec-interactive-debugging]]
=== Interactive Debugging

Interactive debugging, such as setting breakpoints and stepping through code, is not yet supported.
