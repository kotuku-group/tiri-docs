[[ch-structs]]
== Structs
indexterm:[structs] indexterm:[structures] A struct is a first-class value that maps a fixed set of named, typed fields onto a contiguous block of memory with a C/pass:[C++] compatible layout.  The `type()` function returns `"struct"` for a struct instance (see <<sec-structs-type>>).  A struct is a reference type: assigning it to another variable copies the reference, not the payload.  Field access is provided directly on the instance; a struct is not a table and does not respond to table operations other than those defined in this chapter.

Struct definitions originate from two sources:

* The `struct` declaration statement, which defines a new layout directly in Tiri source (see <<sec-struct-declarations>>).
* Kōtuku module IDL definitions, registered through an `include` directive or a `module` declaration (see <<ch-modules>>).  Many class and module functions use structs for returning condensed information.

Both sources produce identical struct values and share the `struct` interface functions defined in <<sec-struct-interface>>.

[cols="1,3",options="header"]
|===
|Property |Guarantee

|Mutation
|Field writes modify the backing memory in place.  Reads and writes to a field are visible through every reference to the same instance.

|Ordering
|Fields have a fixed order determined by the struct definition.  `pairs()` visits fields in declaration order.

|Iteration
|`pairs()` yields each field name and its current value.  The set of fields is fixed by the definition and does not change during iteration.

|Identity
|Two references are equal via `is` when they refer to the same instance.  Distinct instances are never equal, even when their payloads are identical.

|Equality
|Structs are compared by reference identity.  Field-by-field comparison is not performed.

|Performance
|Field access by name is O(1).  Reads and writes of scalar fields on a value annotated as `struct` compile to dedicated bytecodes (see <<ch-performance-and-the-jit>>).
|===

[[sec-struct-declarations]]
=== Struct Declarations
indexterm:[struct declarations] The `struct` declaration statement registers a new struct definition.  The declaration begins with the `struct` keyword and the definition name, lists the fields, and terminates with the `end` keyword:

[source,tiri]
----
struct User
   Name: str
   Age: int
   Enabled: bool
end

user = struct<User> { Name='Alice', Age=30 }
print(user.Name, user.Age)   -- Alice  30
----

Each field is declared as `Name: type`, where `type` is one of the official field types listed in <<sec-struct-field-types>>.  Fields are separated by commas or newlines; both separators are interchangeable within the same declaration.

A declaration does not bind the definition name as a variable or constructor.  Instances are constructed through the explicit `struct<Name>` form described in <<sec-struct-construction>>, or through the `struct` interface functions in <<sec-struct-interface>>.

[discrete]
==== Semantics

* Declarations are permitted at the top-level scope of a source file only.  A declaration inside a function or block raises a parse error.
* The definition is registered at parse time for the current script.  A declaration binds no variable and emits no bytecode; it registers the layout only.
* The definition interoperates with the `struct` interface: `struct.new('User')` and `struct.size('User')` resolve declarations by name.
* Re-declaring a name with an identical layout is permitted and has no effect.  Re-declaring a name with a different layout raises a parse error that reports the location of the original declaration.
* `struct` is not a reserved word.  The declaration form is recognised contextually at statement position, and `struct` remains usable as an identifier.

[discrete]
==== Errors

The following conditions raise a parse error:

* A definition name containing non-alphanumeric characters.
* A brace following the definition name.  Declarations use `end` termination; braces are reserved for `struct<Name> { pass:[...] }` construction.
* A declaration with no fields.
* The same field name declared more than once.  Names that differ in letter case are distinct and may coexist.
* An unrecognised field type name.
* A `struct<Name>` or `ptr<Name>` reference to a definition that has not been registered yet.  Forward references are not supported; declarations must precede use.
* An `array<type>` field with an unsupported element type or a declared dimension (see <<sec-struct-dynamic-arrays>>).
* A layout whose total size exceeds the supported struct size range.

[[sec-struct-construction]]
[discrete]
==== Construction

[.api]`instance = struct<Name> [{ Fields }]`

The explicit `struct<Name>` construction form creates an instance of the layout `Name`.  `Name` must reference a definition that has already been registered; a reference to an unregistered definition raises a parse error.

The initialiser table is optional.  Omitting it constructs a zero-initialised instance, as does supplying an empty table: numeric fields read `0`, `bool` fields read `false`, string fields read `''`, object and pointer fields read `nil`, and dynamic array fields read as empty arrays.  When `Fields` is present, its key-value pairs are applied to the corresponding fields after zero-initialisation.  Field values are subject to the assignment rules defined in <<sec-struct-field-access>>; a value that the target field does not accept raises an exception.

[source,tiri]
----
empty = struct<User>
same  = struct<User> { }
user  = struct<User> { Name='Alice', Age=30, Enabled=true }
----

[discrete]
==== Fixed Arrays

Append `[N]` to a type to declare a fixed-size array of `N` elements, where `N` is a positive integer.  The field occupies `N` times the element size.  A `char[N]` field declares a character buffer that is read as a string:

[source,tiri]
----
struct Sample
   Buffer: char[16]
   Fixed: int[3]
end
----

Fixed arrays of `str` are not supported and raise a parse error.

[[sec-struct-dynamic-arrays]]
[discrete]
==== Dynamic Arrays

indexterm:[struct array fields] The `array<type>` field type declares a dynamically sized array whose storage is owned by the struct and resizes on assignment:

[source,tiri]
----
struct Palette
   Names:  array<str>
   Values: array<int>
end

palette = struct<Palette> { Values=array<int> { 1, 2, 3 } }
palette.Values = array<int> { 8, 9, 10, 11, 12 }   -- resizes to five elements
----

The element type may be any scalar numeric type from the table above, `str`, or `struct<Name>` where `Name` references a registered definition whose fields are all trivially owned (a definition containing owned `str` or `array` fields is rejected).  Element types that own external resources -- `cstr`, `ptr`, `obj`, `func` and nested `array` types -- raise a parse error.

A dynamic array field cannot declare a dimension: both `array<type, N>` and `array<type>[N]` raise a parse error.  A newly constructed instance reads dynamic array fields as empty arrays.

Reading a dynamic array field produces an array holding a copy of the field's current elements; the result does not track subsequent changes to the field.  `struct.clone()` and `struct.copy()` deep-copy dynamic array fields, so the copy holds independent storage.

The materialised array retains the signedness and width of the declared field, so `arr.type()` reports the unsigned element type for an unsigned field:

[source,tiri]
----
struct Counters
   Signed:   array<int16>
   Unsigned: array<uint>
end

value = struct<Counters> { Unsigned=array<uint> { 4000000000 } }
value.Unsigned.type()   -- 'uint'
value.Signed.type()     -- 'int16'
----

The one exception is the unsigned byte-sized categories.  A field declared as `array<bool>`, `array<char>`, `array<byte>` or `array<uint8>` materialises as a byte array, and `arr.type()` reports `'byte'` for all four.  An `array<int8>` field is not folded into that group: it materialises as a signed `int8` array, `arr.type()` reports `'int8'`, and the elements read back in the range −128--127.  See <<sec-uint8-versus-byte>>.

[source,tiri]
----
struct Samples
   Buffer: array<byte>
   Signed: array<int8>
end

value = struct<Samples> { }
value.Signed = array<int8> { -128, 127 }
value.Signed.type()   -- 'int8'
value.Signed[0]       -- -128
value.Buffer.type()   -- 'byte'
----

A fixed-dimension field follows the same rule: `int8[N]` materialises as an `int8` array, whereas `byte[N]` and `uint8[N]` materialise as byte arrays.

Writing a byte-sized array field requires the matching element type.  An `array<int8>` field accepts only an `array<int8>` source, and the unsigned byte-sized fields accept only an `array<byte>` source.

[[sec-struct-typed-references]]
=== Typed References
indexterm:[struct annotations] The annotation `struct<Name>` constrains a local variable, function parameter or return value to instances of the declared layout `Name`.  The plain `struct` annotation accepts any struct instance.  See <<ch-type-system>> for general annotation semantics.

`struct<Name>` is an exact runtime contract: the value must be an instance of the registered definition `Name`.  An instance of a different definition is rejected even when both definitions declare identical fields.  A mismatch raises a catchable exception naming both layouts (see <<sec-runtime-type-contracts>>).

[source,tiri]
----
function age(Value: struct<User>): num
   return Value.Age
end

local typed: struct<User> = struct<User> { Age=30 }
----

Annotating a value with its layout enables the compiler to resolve field offsets statically (see <<ch-performance-and-the-jit>>).

[[sec-struct-interface]]
=== The struct Interface

The functions that take an instance as their first argument are also callable as built-in methods on that instance: `instance.clone()` is equivalent to `struct.clone(instance)`.  See <<sec-built-in-method-calls>>.

==== struct.new()

[.api]`instance = struct.new(StructName, [Fields])`

Creates a new struct instance from a registered definition identified by `StructName`.  The definition must have been registered through an `include` directive, a `module` declaration (<<sec-module-declarations>>), or a `struct` declaration (<<sec-struct-declarations>>).  Raises an exception if the definition is not found.  Returns a value whose `type()` is `"struct"`.

`Fields` must be a table if specified, and the key-value pairs are applied to the corresponding struct fields during creation.  Field values are subject to the assignment rules defined in <<sec-struct-field-access>>; a value that the target field does not accept raises an exception.

[source,tiri]
----
include 'vector'

-- Create with default (zeroed) values
stop = struct.new('GradientStop')
stop.offset    = 0.5
stop.rgb.red   = 1.0
stop.rgb.green = 0.0
stop.rgb.blue  = 0.0
stop.rgb.alpha = 1.0

-- Create with initial field values
stop = struct.new('GradientStop', { offset = 0.5 })
----

==== struct.size()

[.api]`bytes = struct.size(Target)`

Returns the byte size of a struct definition.  `Target` is either the name of a registered definition or a struct instance, in which case the size of that instance's definition is returned.  Raises an exception if `Target` names a definition that is not found, or if `Target` is neither a struct nor a string.

[source,tiri]
----
entry = struct.new('User')
struct.size('User')    -- size of the definition
struct.size(entry)     -- the same size, reached through the instance
entry.size()           -- equivalent instance method
----

==== struct.clone()

[.api]`copy = struct.clone(Source)`

Creates a new struct instance of the same definition as `Source` and deep-copies its payload into the new instance.  Owned pass:[C++] string and vector fields are duplicated so that the copy holds independent storage; subsequent modifications to `Source` do not affect the returned instance.  Raises an exception if `Source` holds an unsupported field type.

[source,tiri]
----
source = struct.new('CopyRecord', { count = 12, name = 'source' })
copy   = struct.clone(source)
source.name = 'changed'
print(copy.name)   -- 'source'
----

==== struct.copy()

[.api]`dest = struct.copy(Dest, Source)`

Deep-copies the payload of `Source` into the existing `Dest` instance and returns `Dest`.  `Dest` and `Source` must share the same definition; a mismatch raises an exception with `ERR_Mismatch`.  Raises an exception if either payload is null, if the payloads overlap in memory, or if the definition holds an unsupported field type.

==== struct.toTable()

[.api]`snapshot = struct.toTable(Source)`

Creates a new table with a copy of values from `Source`.  Nested structures are converted recursively, strings and arrays are copied, and repeated or cyclic structure pointers retain their identity within the resulting table graph.

Use this operation when a table-only API, serialiser or application-specific field requires a mutable table; or if the struct values are volatile.  Ordinary field reads should use the struct directly.

[[sec-returned-structs]]
==== Native Results and Ownership

Structure results from module functions, object actions and object methods are read-only by default; assigning one of their fields raises `ERR_ReadOnly` in interpreted and JIT-compiled code.  Only a native descriptor that explicitly marks the result as a writable resource allows write access.

If a struct result is allocated, ownership is passed to Tiri and is not released until collection.  Borrowed results remain owned by their native provider; use `toTable()` when a detached snapshot must outlive that provider.

`clone()` creates an independent writable value when the registered layout supports cloning.  `copy()` rejects a read-only destination.

=== Instance Methods

==== size(), clone(), copy() and toTable()

`size()`, `clone()`, `copy()` and `toTable()` are reachable as built-in methods on an instance.  Fields sharing these names are still treated as fields when not invoked as functions.

==== Length Operator

The `#` operator returns the total number of fields in the struct.

[[sec-struct-field-access]]
=== Field Access

Fields are read and written directly on the instance using dot or bracket notation.  Field names are matched case-sensitively.
Reading or writing a name that the definition does not declare exactly raises an exception.

A write validates the category of the value against the field before any storage is changed.  The categories are exact and no conversion between them is attempted: a boolean field accepts only a boolean, a numeric field only a number, and an owned string field only a string.  A value of the wrong category raises `ERR_InvalidType` and leaves the field at its previous value, so a numeric string does not satisfy a numeric field, and a number does not satisfy a boolean field, a string field or a character buffer.

`nil` is accepted only where the field has a defined empty state.  A numeric field accepts `nil` and stores zero.  An object or pointer field accepts `nil` and clears the field.  A boolean field and an owned string field reject `nil` with `ERR_InvalidType` and retain their previous value.

The value produced by a read, and the values accepted by a write, depend on the field's declared type:

[cols="1,3",options="header"]
|===
|Field category |Behaviour

|Boolean (`bool`)
|Reads and writes a boolean.  `nil` and every other category raise an exception.

|Scalar numeric (`char`, `int8`, `byte`, `int16`, `int`, `int64`, `float`, `double` and unsigned variants)
|Reads and writes a number, converted as defined in <<sec-struct-numeric-conversion>>.  Unsigned fields preserve the full unsigned range of the storage width.  `nil` stores zero.

|Object (`obj`, `obj<Class>`)
|Reads as a native object (`type()` is `"object"`), or `nil` when unset.  Accepts an object or `nil` on assignment; assigning `nil` clears the field.  A constrained field (`obj<Class>`) accepts instances of the named class or a sub-class of it; any other class raises an exception.  Assigning a detached object wrapper raises an exception.

|Owned string (`str`)
|Reads and writes a string.  The struct owns the string storage.  `nil` raises an exception.

|Raw C string (`cstr`)
|Reads a string, or `nil` when the pointer is null.  Assignment is not supported and raises an exception.

|Character buffer (`char[N]`)
|Reads as a string.  Accepts a string or byte array on assignment.

|Pointer (`ptr`)
|A null pointer reads as `nil`; a non-null pointer reads as light userdata.  Accepts light userdata or `nil` on assignment; every other category raises an exception.

|Struct pointer (`ptr<Name>`)
|A null pointer reads as `nil`; a non-null pointer reads as a struct view over the referenced memory.

|Array pointer (`ptr<type[]>`)
|A null pointer reads as `nil`; a non-null pointer reads as an array over the null-terminated elements.

|Function reference (`func`)
|Reads as `nil`.  Assignment is not supported and raises an exception.

|Embedded struct (`struct<Name>`)
|Reads as a struct view over the embedded field, or an array of views for an embedded array.  The view keeps the enclosing instance alive.

|Dynamic array (`array<type>`)
|Reads as an array holding a copy of the current elements.  Accepts an array or sequential table on assignment; the field resizes to match the source and copies its elements.
|===

Array fields accept an array value on assignment:

* A fixed array (`type[N]`) copies elements from the source array.  A source shorter than `N` clears the remaining elements; an empty array clears the field.  A source longer than `N` raises an exception.
* A dynamic array field (`array<type>`, or a pass:[C++] vector in a module-defined struct) resizes to match the source array and copies its elements.
* A dynamic array of struct elements (`array<struct<Name>>`) accepts an array of tables, where each table's key-value pairs populate the fields of the corresponding element.
* An element type that does not match the field's declared type raises an exception.

[source,tiri]
----
value.fixed = array<int> { 4, 5, 6 }    -- copies three elements
value.fixed = array<int> { 9 }          -- { 9, 0, 0 }
value.dynamic = array<int> { 8, 9, 10 } -- resizes and copies
value.points = array<table> {           -- struct element vector
   { red=1, green=2, blue=3 },
   { red=4, green=5, blue=6 }
}
----

[[sec-struct-numeric-conversion]]
==== Numeric Conversion

A number written to an integer field is truncated toward zero, then validated against the representable range of the field.  A truncated value outside that range raises `ERR_OutOfRange` and leaves the field unchanged; it does not wrap and does not saturate.  The range is determined by the width and signedness of the field, so `char`, `byte` and `uint8` accept 0--255 while `int8` accepts −128--127:

[source,tiri]
----
value.Int8 = 12.7    -- stores 12
value.Int8 = -12.7   -- stores -12
value.Int8 = 128     -- error: out of range for int8
value.Char = 255     -- stores 255
value.Char = -1      -- error: out of range for char
value.UInt8 = -1     -- error: out of range for uint8
----

Apply wrapping explicitly when it is required:

[source,tiri]
----
value.Char = 300 & 0xff   -- stores 44
----

An integer field requires a finite value.  Infinity and `NaN` raise `ERR_OutOfRange` and leave the field unchanged.

A `double` field stores any number, including infinity and `NaN`.  A `float` field stores those same special values, but a finite value whose magnitude exceeds the range of single precision raises `ERR_OutOfRange`:

[source,tiri]
----
value.Float = math.huge   -- accepted
value.Float = 3.5e38      -- error: out of range for float
----

These conversions apply wherever a field is written: the `struct<Name> { pass:[...] }` constructor, `struct.new()`, and later assignment all validate and convert alike, and compiled code produces the same results as the interpreter.

[[sec-struct-membership]]
=== Membership

The `in` operator (<<sec-membership-operator>>) reports whether the struct's definition declares a field name.  The test inspects the definition only and never inspects field values, so a field holding zero, an empty string or `nil` is reported as present.  Names are matched exactly, including letter case, under the same rules as field access (<<sec-struct-field-access>>).  A candidate that is not a string reports `false` and raises no error.

[source,tiri]
----
struct Point
   X: int
   Name: str
end

point = struct<Point> { }
'X' in point         -- true
'Name' in point      -- true
'name' in point      -- false: field names are case-sensitive
'Missing' in point   -- false
1 in point           -- false: a non-string candidate never matches
----

Membership reports `true` for exactly the names that `pairs()` yields (<<sec-struct-iteration>>), and the count of such names equals `#inst`.  The result of the test is fixed for a given definition, so it does not change over the lifetime of an instance.

[[sec-struct-iteration]]
=== Iteration

`pairs()` iterates the fields of a struct in declaration order, yielding each field name and its current value.

[source,tiri]
----
value = struct.new('IterableRecord', { count = 7, name = 'sample' })
for name, field_value in pairs(value) do
   print(name, field_value)
end
----

[[sec-struct-tostring]]
=== String Representation

`tostring()` returns the name of the struct definition.

[source,tiri]
----
tostring(struct.new('IterableRecord'))  -- 'IterableRecord'
----
